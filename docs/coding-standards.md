# Test Repository Coding Standards

- Use Java 17.
- Use descriptive package and class names.
- Name tests with Given-When-Then wording where practical.
- Structure tests as Arrange-Act-Assert.
- Assert observable behavior rather than private implementation details.
- Keep test data isolated and deterministic.
- Avoid test order dependencies.
- Use environment variables for URLs and credentials.
- Never log passwords, tokens, API keys, or sensitive user data.
- Use Conventional Commits.
- Resolve formatting and static-analysis findings before opening a pull request.

Review comments use `[blocker]`, `[suggestion]`, `[question]`, or `[nit]` prefixes.
