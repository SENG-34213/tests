# Test Case Template

Each functional test case must document:

| Field | Content |
|---|---|
| Test Case ID | Unique identifier, for example `TC-AUTH-01` |
| Test Case Name | Clear behavior-focused name |
| Related Requirement | SRS/SDS or ticket reference |
| Related Test File | Repository path to the test |
| Test Type | Unit, integration, security, or E2E |
| Priority | P1, P2, or P3 |
| Preconditions | Required users, data, services, or configuration |
| Input | Request, event, or user action |
| Expected Output | Expected status, response, state, or event |
| Actual Output | Filled during execution |
| Status | Pass, Fail, or Blocked |
